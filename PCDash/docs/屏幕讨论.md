# 关于电阻屏、电容屏的讨论

现在用的是这个屏幕（电阻触摸屏）：<https://www.lcdwiki.com/zh/2.8inch_SPI_Module_ILI9341_SKU:MSP2807>

是否可以无缝切换为这个电容屏？<https://www.lcdwiki.com/zh/2.8inch_IPS_SPI_Module_ILI9341>

这里主要讨论以下几个问题：

1. 是否可以 pin2pin 的引脚对应，直接插上？
2. 软件层面是否可以直接支持？
3. 替换后电容屏的使用感受是否要比电阻屏更好？

---

### 1. 是否可以 pin2pin 的引脚对应，直接插上？

**结论：不能无缝替换。显示部分的 SPI 引脚可以对应，但触摸部分的接口从 SPI 变成了 I2C，必须重新接线。**

| 项目 | MSP2807（电阻屏） | IPS 电容屏 |
| :--- | :--- | :--- |
| **触摸芯片** | XPT2046（SPI） | FT6236（I2C） |
| **触摸接口** | SPI（T_CS / T_CLK / T_DIN / T_DO） | I2C（SDA / SCL） + INT |
| **引脚数量** | 多 4 个 SPI 触摸引脚 | 触摸引脚较少，但物理接口与协议不同 |

---

### 2. 软件层面是否可以直接支持？

**结论：不能直接支持，需要修改驱动。**

当前代码使用的是 `TFT_Touch` 库（针对 XPT2046 电阻屏）：

```cpp
TFT_Touch touch = TFT_Touch(TOUCH_CS_PIN, TOUCH_CLK_PIN, TOUCH_DIN_PIN, TOUCH_DO_PIN);
```

如果换成 FT6236 电容屏后，软件层面需要：

1. **更换触摸驱动库**：换用 `Adafruit_FT6206` 或 `Arduino_FT6236` 库。
2. **修改 LVGL 输入设备回调**：修改 `lv_port_indev.cpp` 中的 `touchpad_read_cb`（因为 I2C 读取坐标的方式与 SPI 完全不同）。
3. **删除触摸校准代码**：电容屏出厂已校准，不需要也无法进行电阻屏式的校准。
4. **调整引脚定义**：修改 `config.h` 的引脚定义，配置 I2C 的 SDA 和 SCL 引脚。

> [!TIP]
> 整体软件适配工作量预计在 **半天** 左右，不算复杂，但需要进行上述驱动调整。

---

### 3. 替换后电容屏的使用感受是否要比电阻屏更好？

**结论：显著更好，尤其对当前遇到的滑动触摸问题有本质上的提升。**

| 对比项 | 电阻屏（XPT2046） | 电容屏（FT6236） |
| :--- | :--- | :--- |
| **滑动流畅度** | 容易中途失联（即你当前遇到的滑动问题） | 流畅，检测连续，不会中途断开 |
| **触摸精度** | 需要校准，易产生物理漂移 | 精准，出厂已校，无需校准 |
| **点击手感** | 需要一定力度按压（压力感应） | 轻触即可灵敏响应（电容感应） |
| **多点触控** | 不支持（仅支持单点） | 支持 2 点触控（FT6236 硬件支持） |
| **防误触** | 戴手套、指甲或硬物均可操作 | 必须裸手或使用专用电容笔 |

你现在面临的“实时滑动检测”问题，根本原因就是电阻屏的物理特性限制。换成电容屏后，为了应对断联而设计的 `_swipe_done` 那套复杂 `on-move` 检测可以大幅简化，甚至回归到最基础的 `on-release` 触发也完全没问题，因为电容屏在滑动过程中不会中途失联。

---

### 总结结论

**值得换，但需要改接线 + 改驱动，不是无缝物理替换。**
